## 1. Fundamental proof methods

Chapter 1 introduces four primary proof techniques in Athena: **equality chaining**, **induction**, **case analysis**, and **contradiction**.

### 1.1 Equality chaining

Equality chaining uses the `chain` method to justify that two terms are equal by a sequence of intermediate equalities.  Each step is justified by an axiom or lemma.  A typical pattern is:

```athena
!chain [\
  t1 = t2 [identity1] => \
  t2 = t3 [identity2] => \
  ... => \
  tn = tm [identityK]
]
```

Athena automatically applies symmetry and transitivity to derive the final equality.  For example, in a monoid with operations `*` and `inv`, the following module defines axioms and proves that taking the inverse twice yields the original elementfile:///home/oai/share/Chapter_01_An_overview_of_fundamental_proof_methods.pdf:

```athena
module M {
  # sort declarations
  domain D
  declare *: [D D] -> D
  declare inv: [D] -> D
  # variable declarations
  declare x,y,z: D
  # axioms (assert creates an object name)
  assert left‑id  := (forall x . 1 * x = x)
  assert right‑id := (forall x . x * 1 = x)
  assert right‑inv:= (forall x . x * inv x = 1)
  assert assoc    := (forall x y z . (x * y) * z = x * (y * z))

  # theorem: inv (inv x) = x
  assert inv‑inv :=
    !chain [
      inv (inv x)
        = inv x * inv (inv x) [right‑id] =>
        = inv x * (x * inv x) [right‑inv] =>
        = (inv x * x) * inv x [assoc] =>
        = 1 * inv x [right‑inv, assoc] =>
        = inv x [left‑id]
    ]
}
```

When requesting equality proofs from ChatGPT, clearly list each intermediate equality and the identity/axiom used.  Refer to the corresponding assertion names (e.g. `right‑id`, `assoc`) to justify each step.

### 1.2 Induction

Induction proofs in Athena use the `by‑induction` method.  You provide base cases and step cases as separate assertions and then call `by‑induction` on the theorem you want to prove.  For the natural numbers datatype `N := zero | (S N)`, the theorem `zero + n = n` is proven by induction over `n`file:///home/oai/share/Chapter_01_An_overview_of_fundamental_proof_methods.pdf:

```athena
module PlusProof {
  domain N
  declare plus: [N N] -> N
  declare zero: N
  declare S: [N] -> N
  declare n: N

  # axioms for addition
  assert Plus‑zero  := (forall n . plus zero n = n)
  assert Plus‑S     := (forall m n . plus (S m) n = S (plus m n))

  # base case lemma
  assert plus‑zero‑id := (forall n . plus zero n = n)

  # step case lemma
  assert plus‑ind‑step :=
    (forall m n . plus (S m) n = S (plus m n))

  # final theorem: zero + n = n
  assert zero‑plus‑id :=
    by‑induction
      (forall n . plus zero n = n)
      with base [plus‑zero‑id]
      and step [
        assume m n .
        plus (S m) n = S (plus m n) [plus‑ind‑step]
      ]
}
```

In general, provide the pattern of induction: specify the theorem with `forall` quantifiers; create base case and step case assertions; call `by‑induction` referencing these assertions.

### 1.3 Case analysis

Case analysis is done using `two‑cases` or `cases` constructs.  You supply separate proofs for each disjunct (e.g. when a boolean proposition is true or false).  The book’s logic puzzle example demonstrates splitting into two cases and augmenting assumptionsfile:///home/oai/share/Chapter_01_An_overview_of_fundamental_proof_methods.pdf#:~:text=%28%21%20two,at%20George:

```athena
# Suppose we have propositions A and B and want to prove P.
# We can do:
!two‑cases [
  assume A .
    # use A to derive P1
    P1
  assume ~A .
    # use not A to derive P2
    P2
  conclude P from P1 and P2
]
```

Athena also provides the method `augment` to conjoin assumptions inside a chain proof and `existence` to existentially generalize a witness.  These methods can be used within case proofs as part of the justification listfile:///home/oai/share/Chapter_06_Implication_chaining.pdf#:~:text=method%2C%20call%20it%20augment%2C%20that,pass%20from%20any%20sentence%20p.

### 1.4 Proof by contradiction

To prove a statement `P` by contradiction, use `by‑contradiction` combined with `assume` and `absurd`.  You assume `~P` and derive a contradiction, then call `absurd`.  For example, proving the asymmetry of a strict ordering `<` uses a contradiction proof inside a modulefile:///home/oai/share/Chapter_01_An_overview_of_fundamental_proof_methods.pdf#:~:text=When%20proving%20a%20negative%20result%2C,to%20prove%2C%20and%20the%20second:

```athena
module Ord {
  domain A
  declare < : [A A] -> Bool
  # define the strict order axioms (irreflexive, transitive, etc.) ...

  assert asymmetry :=
    by‑contradiction
      assume x y . x < y & y < x
      # derive a contradiction using transitivity and irreflexivity
      absurd
}
```

The `absurd` method requires the assumption base to contain both a proposition and its negation, so ensure your chain or case analysis derives such a contradiction.

## 2. Introduction to Athena

Chapter 2 introduces the language of Athena: **terms**, **sentences**, **function symbols**, **procedures**, **variables**, **sorts**, and basic **list operations**.

### 2.1 Terms vs. sentences and function symbols vs. procedures

Athena is a typed language for constructing *terms* (data values) and *sentences* (logical propositions).  A **function symbol** (like `plus`) represents an uninterpreted operation and cannot be executed, while a **procedure** can compute new terms.  For example, here is a factorial procedure using built‑in numeric procedures `less?`, `times`, and `minus`file:///home/oai/share/Chapter_02_Introduction_to_Athena.pdf#:~:text=define%20,minus%20n%201%29%29%29:

```athena
# factorial procedure on natural numbers
define (fact n:N) :=
  check (less? n 1)
    then 1
    else (times n (fact (minus n 1)))
```

In the above, `check` takes a boolean test and returns one of two expressions.  Because `less?`, `times`, and `minus` are built‑in procedures on numbers, `fact` returns a number.  If you attempt to call a function symbol (like `plus`) as if it were a procedure, Athena will error.  Keep this distinction clear in requests.

### 2.2 Variables and sorts

Variables carry sort annotations.  A variable `?i : N` ranges over natural numbers, while sort can sometimes be inferred.  Use colon notation if needed.  For lists, the sort is `List S` for a list of `S` elements.  Primitive list procedures include:

- `add(x l)` — add element `x` to front of list `l`.
- `head(l)` — first element of `l`.
- `tail(l)` — list without the first element.
- `rev(l)` — reverse `l`.
- `length(l)` — length of `l`.
- `join(l1 l2)` — concatenation of `l1` and `l2`.

Example: compute the list of squares of numbers 1–3 using `map` and a locally defined `square` procedurefile:///home/oai/share/Chapter_02_Introduction_to_Athena.pdf:

```athena
# define square procedure
define (square n:N) := (times n n)

# map square over [1 2 3]
define squares := (map (lambda (n:N) (square n)) [1 2 3])
```

### 2.3 Methods and procedural definitions

A **method** is a procedure that produces a *proof* rather than a term.  Methods operate on the **assumption base** at call time.  The `commute‑and` method swaps the order of a conjunction by applying `left‑and` and `right‑and` to obtain each conjunct, then conjoining them in reverse orderfile:///home/oai/share/Chapter_02_Introduction_to_Athena.pdf:

```athena
method commute‑and (p, q) :=
  !chain [
    (p & q) ==> q [right‑and] ==> p [left‑and]
  ] by (both)
```

When defining methods or procedures that pattern‑match on terms, you can use `match`.  For example, the `break‑sentence` procedure splits a sentential constructor into its constructor and reversed argument listfile:///home/oai/share/Chapter_02_Introduction_to_Athena.pdf:

```athena
# break a sentence s into (constructor arguments)
define (break‑sentence s) :=
  match s {
    ((some‑sent‑con pc) (some‑list args)) => [pc (rev args)]
    _ => error
  }
```

## 3. Proving equalities and recursive definitions

Chapter 3 covers definitions by recursion and equational reasoning.

### 3.1 Defining recursive functions and axioms

The natural numbers `N` are defined as a datatype, and operations like addition and multiplication are declared with axioms.  For example, addition `plus` on naturals is declared with two axioms: **right‑zero** and **right‑nonzero**file:///home/oai/share/Chapter_03_Proving_equalities.pdf:

```athena
module NPlus {
  domain N
  declare plus: [N N] -> N
  declare zero: N
  declare S: [N] -> N

  assert right‑zero   := (forall n . plus n zero = n)
  assert right‑nonzero:= (forall m n . plus m (S n) = S (plus m n))
}
```

Similarly, multiplication `times` is defined via `Times-zero` and `Times-nonzero` axioms and one can prove `x * one = x` using a chainfile:///home/oai/share/Chapter_03_Proving_equalities.pdf:

```athena
module NTimes {
  domain N
  declare times: [N N] -> N
  declare zero one: N
  declare S: [N] -> N

  assert times-zero   := (forall m . times m zero = zero)
  assert times-nonzero:= (forall m n . times m (S n) = plus (times m n) m)

  assert times-right-one :=
    !chain [
      times x one
        = times x (S zero) [definition of one] =>
        = plus (times x zero) x [times-nonzero] =>
        = plus zero x [times-zero] =>
        = x [right-zero]
    ]
}
```

When requesting function definitions, specify the name, argument sorts, and axioms.  Provide derived lemmas (like `times-right-one`) to enable chain proofs.

### 3.2 Chain proofs for specific computations

To compute a sum or product of concrete naturals, instantiate the axioms using `instance` and then chain.  For example, to show `2 + 2 = 4` (where `two` and `four` are numerals `S (S zero)` and `S (S (S (S zero)))`), one can use a chain referencing the axiomsfile:///home/oai/share/Chapter_03_Proving_equalities.pdf:

```athena
# define numerals
assert two := S (S zero)
assert four := S (S (S (S zero)))

# prove two + two = four
assert plus-two-two :=
  !chain [
    plus two two
      = plus (S (S zero)) two [definition of two] =>
      = S (plus (S zero) two) [right-nonzero] =>
      = S (S (plus zero two)) [right-nonzero] =>
      = S (S two) [right-zero] =>
      = four [definition of four]
  ]
```

### 3.3 Lists and concatenation

Lists are built with `nil` and `::`.  Concatenation `join` (written `++` in infix notation) is defined by two axioms: appending to an empty list yields the other list; appending to a non-empty list conses the head and recurses on the tail.  The chain below demonstrates concatenating two listsfile:///home/oai/share/Chapter_03_Proving_equalities.pdf:

```athena
module ListJoin {
  domain N
  declare nil : List N
  declare ::  : [N List N] -> List N
  declare join : [List N List N] -> List N infixr 6

  assert join‑nil   := (forall l . nil ++ l = l)
  assert join‑nonempty := (forall x l1 l2 . (x :: l1) ++ l2 = x :: (l1 ++ l2))

  # compute ( [1 0] ++ [1 0 2] )
  assert join‑example :=
    !chain [
      (1 :: 0 :: nil) ++ (1 :: 0 :: 2 :: nil)
        = 1 :: ((0 :: nil) ++ (1 :: 0 :: 2 :: nil)) [join‑nonempty] =>
        = 1 :: (0 :: (nil ++ (1 :: 0 :: 2 :: nil))) [join‑nonempty] =>
        = 1 :: (0 :: (1 :: 0 :: 2 :: nil)) [join‑nil]
    ]
}
```

An induction proof shows that appending `nil` on the right leaves any list unchanged.  Define base and step lemmas and call `by‑induction`file:///home/oai/share/Chapter_03_Proving_equalities.pdf#:~:text=of%20length%20n,nonempty.

### 4.1 Boolean constants and basic methods

Conjunction elimination methods:

```athena
# left-and: from (A & B) derive Afile:///home/oai/share/Chapter_04_Sentential_logic.pdf#:~:text=assert%20p%20%3A%3D%20,the%20corresponding%20connective%20or%20quanti%EF%AC%81er
```

Conjunction introduction uses `both`: if you can derive A and B separately, you can derive `A & B`.  Example: derive `(D & A)` from `(A & B)` and `(C & D)`file:///home/oai/share/Chapter_04_Sentential_logic.pdf#:~:text=assert%20p%20%3A%3D%20,the%20corresponding%20connective%20or%20quanti%EF%AC%81er:

```athena
!let [h1 := assume . (A & B),
      h2 := assume . (C & D)] in

    D [from (right‑and h2)]
    & A [from (left‑and h1)]
  ] by both
```

### 4.2 Conditional reasoning

Use `mp` (modus ponens) and `mt` (modus tollens) for implication:

- `mp` takes a conditional `A ==> B` and a proof of A to derive Bfile:///home/oai/share/Chapter_04_Sentential_logic.pdf.
- `mt` takes `A ==> B` and `~B` to derive `~A`file:///home/oai/share/Chapter_04_Sentential_logic.pdf.

To prove a conditional `A ==> B`, use `assume` to temporarily assume A, derive B, then call `assume` again to discharge the assumptionfile:///home/oai/share/Chapter_04_Sentential_logic.pdf:

```athena
# prove (A ==> C) from (A ==> B) and (B ==> C)
method transitive‑implication :=
  assume [A ==> B, B ==> C] .
  assume A .  # assume antecedent A
    B [mp]    # derive B
    C [mp]    # derive C
  end-assume .
```

## 5. First‑order logic

Chapter 5 introduces quantifiers `forall` and `exists`.  The key points:

- Universal quantification `forall x . P(x)` ranges over the sort of `x`.  Variables in quantifiers may omit the sort if it can be inferred.
- Existential quantification `exists x . P(x)` asserts there exists an `x` satisfying `P(x)`.

When constructing quantifier proofs, the book uses methods for introduction and elimination (shown in later chapters).  A brief example: to prove `forall n . plus zero n = n` we used `by‑induction` above.  To show existence, you might provide a witness and call a built‑in existence introduction method (e.g., `egen*`).

## 6. Implication chaining

In Chapter 6, the book extends equality chains to *implication* chains.  The `chain` method generalizes: each step has the form `p1 ==> p2 [justification]`.  For example, prove `A & ~~B ==> B` by the chainfile:///home/oai/share/Chapter_06_Implication_chaining.pdf#:~:text=Here%20is%20a%20more%20interesting,Theorem%3A%20%28if%20%28and%20A:

```athena
!chain [
  (A & ~~B) ==> ~~B [right‑and] =>
          ==> B    [dn]  # double negation
]
```

Each justification must correspond to a method that derives the implication.  To build more complex chains you may need to **augment** assumptions using the `augment` method, which combines an extra conjunct into the goal.  The `augment` method is defined and used as followsfile:///home/oai/share/Chapter_06_Implication_chaining.pdf#:~:text=method%2C%20call%20it%20augment%2C%20that,pass%20from%20any%20sentence%20p:

```athena
method augment (p q r) :=
  # prove from p ==> q that p ==> q & r
  assume p .
    q [mp]         # from p ==> q
    r              # supply separate proof or assumption
    q & r [both]
  end-assume .
```

The `existence` method generalizes a sentence to an existential quantifier; see the book for detailsfile:///home/oai/share/Chapter_06_Implication_chaining.pdf#:~:text=to%20an%20existential%20generalization%20of,as%20a%20generalization%20of%20both.

## 8. Natural number orderings

Chapter 8 defines the strict less‑than relation `<` on naturals.  A nested module `Less` inside `N` introduces the axiomsfile:///home/oai/share/Chapter_08_Natural_number_orderings.pdf:

```athena
module N {

  module Less {
    declare < : [N N] -> Bool
    assert zero<S := (forall n . zero < (S n))
    assert not-zero := (forall n . ~(n < zero))
    assert injective := (forall m n . (S m) < (S n) = (m < n))

    # derived definitions
    define (=zero n) := (n = zero)
    define (zero< n) := (zero < n)
    define (S1 m n) := (m < n ==> S m < S n)
    # ... etc.

    # proof: if m < n then S m < S n
    assert S‑step :=
      by‑induction
        (forall m n . m < n ==> S m < S n)
        with base [
          # base case: zero < (S n)
          (forall n . zero < (S n)) [zero<S]
        ]
        and step [
          assume m n . m < n ==> S m < S n
          # step: (S m) < (S n) implies ...
```

## 9. Integer representations and proof mappings

Chapter 9 defines integers `Z` as pairs of naturals (pos and neg) and defines addition and negation.  The integers are represented as a datatype with constructors `pos N` and `neg N`.  The module `Z` defines `zero`, `one`, and `+` with axioms for each sign combinationfile:///home/oai/share/Chapter_09_Integer_representations_and_proof_mappings.pdf#:~:text=We%20begin%20by%20de%EF%AC%81ning%20the,Z:

```athena
module Z {
  domain N
  datatype Z := pos N | neg N
  declare zero one: Z
  declare plus : [Z Z] -> Z infixl 5

  assert zero-def  := zero = pos zero
  assert one-def   := one  = pos (S zero)

  # addition axioms
  assert pos-pos  := (forall m n . pos m + pos n = pos (plus m n))
  assert pos-neg1:= (forall m n . (m > n) ==> pos m + neg n = pos (m - n))
  assert pos-neg2:= (forall m n . ~(m > n) ==> pos m + neg n = neg (n - m))
  assert neg-pos1:= (forall m n . (n > m) ==> neg m + pos n = pos (n - m))
  assert neg-pos2:= (forall m n . ~(n > m) ==> neg m + pos n = neg (m - n))
  assert neg-neg  := (forall m n . neg m + neg n = neg (plus m n))

  # negation and subtraction
  declare negate : [Z] -> Z
  assert positive  := (forall m . negate (pos m) = neg m)
  assert negative  := (forall m . negate (neg m) = pos m)
  define (minus a b) := (a + (negate b))
}
```

Proofs about integers often require splitting cases based on the sign of the numbers.  The `datatype-cases` method automatically generates the base cases `pos x` and `neg x` and provides the corresponding assumptions inside each branch.  For example, to show that each integer has a right inverse `(x + negate x = zero)`, we use `datatype-cases` and chainfile:///home/oai/share/Chapter_09_Integer_representations_and_proof_mappings.pdf#:~:text=Right,Negate%20pos%20x%20%3D%20zero:

```athena
assert right-inverse :=
  datatype-cases x:Z  # splits into pos x and neg x
    assume n . x = pos n .
      !chain [
        pos n + negate (pos n)
          = pos n + neg n [positive] =>
          = pos zero [pos-neg1 or pos-neg2 depending on m>n] =>
          = zero [zero-def]
      ]
    assume n . x = neg n .
      !chain [
        neg n + negate (neg n)
          = neg n + pos n [negative] =>
          = pos zero or neg zero [neg-pos1 or neg-pos2] =>
          = zero [zero-def]
      ]
```

Similarly, prove right identity `x + zero = x` and left identity `zero + x = x` using `datatype-cases`file:///home/oai/share/Chapter_09_Integer_representations_and_proof_mappings.pdf#:~:text=Right,neg.

## 10. Fundamental discrete structures

Chapter 10 introduces datatypes for discrete structures like **pairs** and **sets**.  The `Pair` module defines an ordered pair constructor `@` and axioms; the `swap` operation swaps the components of a pair.  The book proves the involutive property of swap: swapping twice yields the original pairfile:///home/oai/share/Chapter_10_Fundamental_discrete_structures.pdf#:~:text=We%20introduce%20a%20swap%20function,y%20%3D%20y%20%40%20x.

```athena
module Pair {
  domain A
  declare @ : [A A] -> PairA infix 5

  # pair axioms: equality on pairs is componentwise
  assert pair-cong := (forall x1 x2 y1 y2 . (x1 = y1 & x2 = y2) ==> (x1 @ x2 = y1 @ y2))

  # swap operation
  define (swap p) :=
    match p {
      (x @ y) => (y @ x)
    }

  # prove swap swap p = p
  assert swap-swap :=
    by‑cases p:PairA  # pattern-match on pair
      assume x y . p = (x @ y) .
        !chain [
          swap (swap (x @ y))
            = swap (y @ x) [definition of swap] =>
            = x @ y [definition of swap]
        ]
```

The `FundamentalDisSet` module deals with set operations.  One key identity is `A \ (A ∩ B) = A \ B`, which is proven by combining set difference and intersection characterization theorems with a chainfile:///home/oai/share/Chapter_10_Fundamental_discrete_structures.pdf#:~:text=tively,B%29%20%5BDC:

```athena
module SetId {
  domain A
  declare \ : [Set A Set A] -> Set A infix 6
  declare ∩ : [Set A Set A] -> Set A infix 7

  assert difference-characterization := ...
  assert intersection-characterization := ...

  assert diff-int-id :=
    !chain [
      A \ (A ∩ B)
        = { x | x ∈ A & x ∉ (A ∩ B) } [difference-characterization] =>
        = { x | x ∈ A & ~(x ∈ A & x ∈ B) } [intersection-characterization] =>
        = { x | x ∈ A & (x ∉ B) } [boolean logic] =>
        = A \ B [difference-characterization]
    ]
}
```

11. A Binary Search Algorithm (Trees) — fun-style specs and proofs
----------------------------------------------------------------------

**Core idea.** Define binary search over BSTs with `fun` (pattern + conditions) and prove two properties: *found* and *not-found*. The book frames the algorithms section and the move to `fun` before presenting binary search; reuse that style. 【6:9†Chapter_10_Fundamental_discrete_structures.pdf†L76-L84】【6:9†Chapter_10_Fundamental_discrete_structures.pdf†L86-L96】

**Template (BST + binary search):**
```athena
module BST {
  # element sort and order
  domain Key
  declare < : [Key Key] -> Bool
  declare = : [Key Key] -> Bool

  # binary tree
  datatype Tree := leaf | (node Tree Key Tree)

  # well-formedness (BST invariant)
  declare bst? : [Tree] -> Bool
  assert* bst-def := [
    bst? leaf
    bst? (node l x r) <== bst? l & bst? r
       & (forall y . in? y l ==> y < x)
       & (forall y . in? y r ==> x < y)
  ]

  # membership (logical)
  declare in? : [Key Tree] -> Bool
  assert* in-def := [
    ~(in? k leaf)
    in? k (node l x r) <== (k = x) \/ in? k l \/ in? k r
  ]

  # binary search: returns Bool
  declare bsearch : [Key Tree] -> Bool
  assert* bsearch-def := (fun [
    (bsearch k leaf) = false
    (bsearch k (node l x r)) =
      [ true              when (k = x)
        (bsearch k l)     when (k < x)
        (bsearch k r)     when (x < k) ]
  ])

  # FOUND: if bst? t & in? k t then bsearch k t = true
  assert bsearch-found :=
    (forall k t . bst? t & in? k t ==> bsearch k t = true)

  # NOT-FOUND: if bst? t & ~in? k t then bsearch k t = false
  assert bsearch-not-found :=
    (forall k t . bst? t & ~(in? k t) ==> bsearch k t = false)
}
```

12. A Fast Exponentiation Algorithm — strong/measure induction + fun
----------------------------------------------------------------------

**Core idea.** Specify fast exponentiation with `fun`: even exponents square the subresult; odd exponents multiply once more. Provide both a straightforward and a tail-recursive accumulator variant. The chapter emphasizes strong and measure induction as proof drivers. 【1:1†Chapter_12_A_fast_exponentiation_algorithm.pdf†L23-L31】

**Template (fast power, four cases including `n=1` optimization):**
```athena
module FastPow {
  domain N
  declare zero one : N
  declare + : [N N] -> N
  declare * : [N N] -> N
  declare half : [N] -> N
  declare even? odd? : [N] -> Bool
  declare parity : [N] -> N  # 0 or 1
  declare S : [N] -> N       # successor

  declare pow : [N N] -> N
  assert* pow-def := (fun [
    (pow a zero) = one
    (pow a (S zero)) = a
    (pow a n) = (pow (a * a) (half n))           when even? n
    (pow a n) = a * (pow (a * a) (half n))       when odd? n
  ])

  # tail-recursive accumulator version
  declare powA : [N N N] -> N    # powA a n acc ≡ a^n * acc
  assert* powA-def := (fun [
    (powA a zero acc) = acc
    (powA a n    acc) = (powA (a*a) (half n) acc)     when even? n
    (powA a n    acc) = (powA (a*a) (half n) (a*acc)) when odd? n
  ])

  # correctness: powA a n 1 = pow a n (prove by strong or measure induction on n)
  assert powA-correct :=
    (forall a n . powA a n one = pow a n)
}
```

```athena
module Monoid {

    (forall x . e * x = x)           # left id
```

```athena
module Memory {
  domain (Memory S)
  domain (Loc S)
  domain (Change S)

  declare \  : (S) [(Memory S) (Change S)] -> (Memory S)
  declare \ : (S,T) [(Memory S) T] -> T           # optional
  declare at : (S) [(Memory S) (Loc S)] -> S
  declare <- : (S) [(Loc S) S] -> (Change S)

  # extensional memory equality
  define equality :=
    (forall M1 M2 . (forall a . M1 at a = M2 at a) <==> M1 = M2)

  # assignment equations (conditional fun package)
  module assign {
    define axioms :=
      (fun [ ((M \ a <- x) at b) =
             [ x       when (a = b)
               (M at b) when (a =/= b) ] ])
    define [equal unequal] := axioms
  }

  define Theory :=
    (theory [] [equality assign.equal assign.unequal] 'Memory)
}
```

17. A Correctness Proof for a Toy Compiler — expressions → stack code
----------------------------------------------------------------------

**Core idea.** Define a small expression language, a stack machine instruction set, a compiler `compile : Expr -> Code`, and prove a *simulation* theorem: executing `compile e` yields the same stack result as evaluating `e`. Chapter 17 sets up the overall pipeline: grammar → machine → compiler → proof. 【6:10†Chapter_01_An_overview_of_fundamental_proof_methods.pdf†L47-L55】

**Typical skeleton (fill instruction set as needed):**
```athena
module ToyCompiler {
  # source expressions
  datatype Expr := const Int | add Expr Expr | mul Expr Expr
  declare evalE : [Expr] -> Int
  assert* evalE-def := (fun [
    (evalE (const n)) = n
    (evalE (add e1 e2)) = (evalE e1) + (evalE e2)
    (evalE (mul e1 e2)) = (evalE e1) * (evalE e2)
  ])

  # target code and machine
  datatype Instr := PUSH Int | ADD | MUL
  datatype Code := [] | (:: Instr Code)
  declare run : [Code List Int] -> List Int
  assert* run-def := (fun [
    (run [] S) = S
    (run (PUSH n :: C) S) = run C (n :: S)
    (run (ADD :: C) (y :: x :: S)) = run C ((x + y) :: S)
    (run (MUL :: C) (y :: x :: S)) = run C ((x * y) :: S)
  ])

  # compiler
  declare compile : [Expr] -> Code
  assert* compile-def := (fun [
    (compile (const n)) = [PUSH n]
    (compile (add e1 e2)) = (compile e1) ++ (compile e2) ++ [ADD]
    (compile (mul e1 e2)) = (compile e1) ++ (compile e2) ++ [MUL]
  ])

  # correctness
  assert compile-correct :=
    (forall e S . run (compile e) S = (evalE e) :: S)
}
```

18. A Simple Imperative Language (While) — big-step semantics & determinism
----------------------------------------------------------------------

**Core idea.** Define abstract syntax for AExp/BExp/Com; use *big-step semantics* for expressions and commands with environments/states modeled as default maps; then prove **determinism** of the semantics by `by-cases` on the inference that evaluates a command. 【0:9†Chapter_18_A_simple_imperative_programming_language.pdf†L439-L475】

**State as default map (reused pattern):**
```athena
module State {
  domain Ide
  domain Val
  structure (DMap Ide Val) := (empty-map Val) | (update (pair Ide Val) (DMap Ide Val))
  declare at : (Ide, Val) [(DMap Ide Val) Ide] -> Val
  assert* at-def := [
    (empty-map d at x = d)
    ([k v] ++ rest at x = v      <== k = x)
    ([k v] ++ rest at x = rest at x <== k =/= x)
  ]
}
```
【6:12†Chapter_10_Fundamental_discrete_structures.pdf†L44-L55】【6:12†Chapter_10_Fundamental_discrete_structures.pdf†L64-L72】

**Syntax + semantics (big-step):**
```athena
module While {
  open State

  datatype AExp := N Int | Var Ide | Plus AExp AExp | Times AExp AExp
  datatype BExp := B Bool | Not BExp | And BExp BExp | Lt AExp AExp
  datatype Com  := Skip | Assign Ide AExp | Seq Com Com | If BExp Com Com | WhileDo BExp Com

  declare aval : [AExp (DMap Ide Int)] -> Int
  declare bval : [BExp (DMap Ide Int)] -> Bool
  assert* aval-def := (fun [
    (aval (N n) s) = n
    (aval (Var x) s) = (s at x)
    (aval (Plus a1 a2) s)  = (aval a1 s) + (aval a2 s)
    (aval (Times a1 a2) s) = (aval a1 s) * (aval a2 s)
  ])
  assert* bval-def := (fun [
    (bval (B b) s) = b
    (bval (Not b) s) = ~(bval b s)
    (bval (And b c) s) = (bval b s) & (bval c s)
    (bval (Lt a1 a2) s) = ((aval a1 s) < (aval a2 s))
  ])

  # big-step command semantics: (c, s) ==> s'
  declare steps : [Com (DMap Ide Int) (DMap Ide Int)] -> Bool
  assert* steps-rules := [
    steps Skip s s
    steps (Assign x a) s (update (pair x (aval a s)) s)
    steps (Seq c1 c2) s u <== steps c1 s t & steps c2 t u
    steps (If b c1 c2) s t <== (bval b s) & steps c1 s t
    steps (If b c1 c2) s t <== ~(bval b s) & steps c2 s t
    steps (WhileDo b c) s t <== ~(bval b s) & (t = s)
    steps (WhileDo b c) s u <== (bval b s) & steps c s t & steps (WhileDo b c) t u
  ]

  # determinism: if steps c s s1 and steps c s s2 then s1 = s2
  assert deterministic :=
    (forall c s s1 s2 . steps c s s1 & steps c s s2 ==> s1 = s2)
}
```

**Notes.**
- The determinism proof proceeds by `by-cases` over the derivation of `steps c s s1`, matching the rule used and showing the corresponding rule must also have been used in the second derivation. 【0:9†Chapter_18_A_simple_imperative_programming_language.pdf†L543-L564】

```athena
  datatype Term := Var Ide | Sym Ide | App Ide (List Term)

  datatype Rule := (clause Atom (List Atom))     # Head :- Body*
  datatype Prog := [] | (:: Rule Prog)

  # One-step SLD-like reduction on goal lists under program
  declare sld : [Prog (List Atom) (List Atom)] -> Bool

  # Axiomatic step rules (sketch)
  assert* sld-rules := [
    # resolution against first matching clause, with capture-avoiding substitution σ
    # sld P (G1 :: Gs) (Bodyσ ++ Gs) <== (clause H Body) in P & unify(G1,H) = SOME σ
    # (formalize 'member' and 'unify' separately in Athena)
  ]
}
```

**Notes.**
- Keep unification and substitution as separate Athena definitions (e.g., `unify : [Term Term] -> Option Subst`), with algebraic lemmas proved once and reused.

Manual for Athena Code Creation: Chapters 21–22
=================================================

This final installment distills the **Athena Reference** (Ch. 21) and the **Bibliography + Glossary** (Ch. 22) into a pure–Athena, code‑oriented cheat‑sheet. It focuses exclusively on **syntax, semantics, deduction forms, pattern matching, and reusable snippet templates**. You can paste these snippets into Athena with minimal edits.

Conventions
-----------
- Code blocks are Athena; comments use `#`.
- “Expression” (`E`) vs “Deduction” (`D`) mirrors the Reference’s split. 
- Snippets prefer total, well‑sorted forms; where a precondition exists, it’s spelled out inline.
- When you need side‑effects, use `cell/ref/set!`, `while`, vectors; otherwise stick to pure terms/methods.


B.1 Syntax — What You Can Write
--------------------------------

**Expressions (E).** The reference grammar includes identifiers, chars/strings, unit `()`, term variables `?x:S`, meta‑identifiers `'K`, conditionals `check`, lambdas, applications `(E F*)`, lists `[F*]`, methods, `let/letrec`, `match`, `try`, cells/refs/assignments, loops, vectors, sequences `(seq ...)`, and short‑circuit `(&&)` / `(||)` (see Figures for full grammar).

Minimal templates for each:

```athena
# identifiers, characters, strings, unit
define id-val := x
define a-char := '\65        # 'A
define a-str  := "hello\n"   # list of chars
define unit   := ()

# term vars (annotated or not) and meta-identifiers
define (use-term ?n:Int) := (plus ?n 1)
define a-meta := 'Foo
```

```athena
# conditional expressions
define (abs n:Int) :=
  check { (less? n 0) => (minus 0 n)
        | else       => n }
```

```athena
# procedures and application
define add2 := (lambda (x y) (plus x y))
define seven := (add2 3 4)
```

```athena
# lists
define xs := [1 2 3]
```

```athena
# methods (deductions as values)
method conj (p q) := !both p q
```

```athena
# let / letrec
define sum3 :=
  let {a := 1; b := 2; c := 3} (plus a (plus b c))

letrec { fact := (lambda (n) (check { (equal? n 0) => 1
                                    | else         => (times n (fact (minus n 1))) })) }
  (fact 5)
```

```athena
# match and try
define (sign n:Int) :=
  match (less? n 0) {
    true  => -1
    false => (check { (equal? n 0) => 0 | else => 1 })
  }

define (safe-div a b) :=
  try { (divide a b) | "division error" }
```

```athena
# cells/refs/assignments; while loops
let {c := (cell 0)} 
  (seq (set! c 10) (while (less? (ref c) 100) (set! c (times (ref c) 2))) (ref c))
```

```athena
# vectors
let {v := (make-vector 3 0)}
  (seq (vector-set! v 1 42) (vector-sub v 1))
```

```athena
# sequences; short-circuit boolean ops
(seq E1 E2 E3)
(&& P Q R)   # stops at first false
(|| P Q R)   # stops at first true
```

**Deductions (D).** Method calls `(!M args)`, `conclude`, `assume` (named/unnamed), `suppose-absurd` (proof by contradiction), quantifier intro (`generalize-over`, `pick-any`), existential intro/elims (`with-witness`, `pick-witness`), **structural** `by-induction`, `datatype-cases`, and deduction‑forms of `check`, `match`, `let/letrec`, `try`.

Reusable shells:

```athena
# method call: arguments that are deductions contribute their conclusions
!some-method arg1 arg2  # or (apply-method some-method arg1 arg2)
```

```athena
# conclude: ensure the derived sentence equals the given one
conclude (P ==> Q)
  (!trans P Q)          # body must yield exactly (P ==> Q)
```

```athena
# hypothetical reasoning
assume P .
  Q
end-assume .            # returns (P ==> Q)
```

```athena
# contradiction
suppose-absurd ~P .
  false                 # derive false under ~P
end-suppose .           # yields P
```

```athena
# forall introduction
pick-any x:S .
  R x
end-pick .              # yields (forall x:S . R x)
```

```athena
# exists with explicit witness variable
with-witness ?w:S (exists x:S . R x) .
  R ?w
end-ww .
```

```athena
# structural induction (on a datatype S)
by-induction (forall t:S . P t) {
  base-pattern1 => D1
| base-pattern2 => D2
| (constr sub1 ... subk) => Dstep   # IHs available for recursive components
}
```

```athena
# structural cases (no IHs)
datatype-cases t:S {
  p1 => D1 | p2 => D2 | ...
}
```


B.2 Values — What Your Phrases Denote
--------------------------------------

Athena values include: unit `()`, **function symbols**, **terms**, **sentences**, **connectives and quantifiers** as first‑class values, lists of values, **function values** (from `lambda`), **method values** (from `method`), characters, substitutions, tables/maps, cells, and vectors.

Equality highlights for code writers:
- A Boolean‑sorted term is also a **sentence**; coerces as needed.
- `equal?` is **undefined** for function or method values (attempting comparison is an error).
- Constant symbols can coerce to terms and vice‑versa.
- Cells/vectors compare by identity; contents may be equal while cells are not.

Quick probes:

```athena
(equal? () ())              # true
(equal? 'and 'and)          # true (connective)
(equal? (cell 1) (cell 1))  # false: distinct locations
(equal? (lambda (x) x) (lambda (x) x)) # error: functions not comparable
```


B.3 Operational Semantics — How It Runs
---------------------------------------

Think in terms of four ambient components: **environment** ρ (identifier→value), **assumption base** β (finite set of sentences), **store** σ (mutable cells/vectors), and **symbol set** γ (declared function symbols & sorts). Evaluating any phrase returns either `(V, σ')`, an **error with σ'**, or **diverges**.

Key execution rules that matter for writing correct snippets:

1) **check** evaluates guards sequentially; first `true` selects the branch; `else` is allowed as last; non‑Boolean guards are errors.
```athena
check { P1 => E1 | P2 => E2 | else => E3 }
```

2) **lambda/method** evaluate their bodies in **captured lexical** ρ, but with the **current β and σ** at call time.

3) **application** cases you’ll actually hit:
   - Function value: evaluate args left‑to‑right, thread σ, then apply.
   - Function symbol of arity n: build the **term** `(f t1 … tn)` (sort‑checked).
   - Sentential connective: build `(◦ p1 … pn)`.
   - Quantifier: `(Q x1 ... xk p)` construction requires variables then a sentence.
   - Substitution value θ: `(θ t)` and `(θ [t1 ... tn])` apply θ (sort‑checked).
   - Map: `(m key)` looks up key; missing key is an error.

4) **match** (expressions/deductions): discriminant is evaluated, patterns tested in order; first success binds names and may **refine sorts**; failure errors.

5) **let** desugars to `match`; **letrec** allocates **cells** then uses `set!` with `(ref Ii)` to tie recursion.

6) **try** backtracks across alternatives until one succeeds (or all fail).

7) **Cells/Vectors** are the side‑effect core:
```athena
let {c := (cell 0)} (seq (set! c 5) (ref c))         # 5
let {v := (make-vector 2 0)} 
  (seq (vector-set! v 0 9) (vector-sub v 0))         # 9
```

8) **while** threads σ; guard must be Boolean; any non‑Boolean is an error.

9) **Method call `!M`**: before invoking `M`, any **argument that is a deduction contributes its conclusion to β** (huge for tactics that consume lemmas).

10) **Induction engine**: `by-induction` requires a universally quantified goal over a datatype sort; generates IHs automatically for recursive subcomponents and even **nested IHs** when you nest inductions (e.g., lists inside syntax trees).


B.4 Pattern Matching — Precise, Sort‑Aware
------------------------------------------

The pattern language covers variables (with/without sort), wildcards, named binds `(bind I π)` / `(I as π)`, **list patterns** `[ ... ]`, `(list-of head tail)` and `(split left right)`, **constructor patterns** `(C π1 ... πk)`, **filters** `(some-XXX J)` for specific value classes (var, atom, sentence, list, cell, vector, proc, method, symbol, table, map, sub, char), and **quantifier/connective patterns**. Matching produces an **environment** of bindings and a **sort valuation** for polymorphic refinement.

Pocket patterns:

```athena
# fixed-length list
match xs {
  [x y z] => (plus x (plus y z))
  _       => 0
}

# list-of (head/tail)
match xs {
  (list-of h t) => h
  _             => 0
}

# split: greedy left prefix satisfying the right pattern
match ys {
  (split prefix [last]) => prefix
}

# constructor (datatype) patterns
datatype-cases t:Tree {
  leaf            => P0
| (node l x r)    => P1 l x r
}
```

```athena
# filter examples
match v {
  (some-var x)      => x
| (some-atom p)     => p          # Boolean-sorted term (atomic sentence)
| (some-sent-con c) => c          # 'and, 'or, etc.
| (some-list L)     => L
| (some-method m)   => m
| _                 => v
}
```

**Named binds** preserve the whole value while destructuring:
```athena
match t {
  (bind whole (S n)) => whole   # whole is term (S n)
}
```

**Quantifier pattern** sketch:
```athena
match phi {
  (forall [x y] p) => p                 # pulls prefix quantifiers
| (exists [x] p)   => p
| _                => phi
}
```


Reference‑Backed “Gotchas” and Idioms
-------------------------------------

- Don’t compare functions/methods with `equal?`; design **extensional tests** (apply them and compare results) instead.
- Applications to function symbols or connectives **build terms/sentences** and **must be well‑sorted**; if not, you get an error—push sort annotations earlier.
- `!method` gets extra power from deduction‑arguments; leverage small helper deductions to seed β with lemmas just in time.
- `letrec` uses **cells** under the hood; avoid relying on evaluation order other than what the spec guarantees (left‑to‑right, store‑threaded).
- `by-induction` patterns must be **proper** and **jointly exhaustive** for the datatype; step cases automatically receive IHs for recursive fields (and nested structures, when applicable).

Glossary Signals (for code authors)
-----------------------------------

- **Free vs bound variables:** standard FOL; substitution avoids **capture**.
